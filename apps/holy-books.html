How it works

The data

The page reads only realm-scripture-vocabulary's parent types — HolyBook, ScriptureChapter, Verse — so it answers from every scripture realm installed in this world: today the Bible (King James), the Quran (Pickthall, with the Arabic), the Tanakh (JPS 1917, with the Hebrew), the Book of Mormon, the Doctrine and Covenants and the Pearl of Great Price. Their verses are reference data seeded once at install and unchanging. Each chapter is also a document, chunked and embedded when its realm is installed, tagged scripture and its scripture's slug; that is what the meaning search ranks. Counterparts across scriptures (CORRESPONDS_TO) are derived by the scripture realms from pairings their builds checked word by word against the King James.

The views, and the Cypher that runs

Scriptures

the columns — every scripture installed, with its tradition and translation.

MATCH (h:HolyBook)
RETURN h.scripture AS scripture, h.name AS name, h.tradition AS tradition,
       h.originalLanguage AS originalLanguage, h.translation AS translation,
       h.chapterCount AS chapters, h.verseCount AS verses
ORDER BY scripture

WordAcrossScriptures

the bars — verses using the word, per thousand verses.

MATCH (v:Verse)
WITH v.scripture AS scripture, count(v) AS verses,
     sum(CASE WHEN toLower(v.text) CONTAINS toLower($term) THEN 1 ELSE 0 END) AS matching
RETURN scripture, matching, verses,
       round(1000.0 * matching / verses, 2) AS perThousandVerses
ORDER BY perThousandVerses DESC

SearchScriptures

“Verses using the word” — the first few in each scripture, with the chapter each opens.

MATCH (v:Verse)
WHERE toLower(v.text) CONTAINS toLower($term)
WITH v ORDER BY v.scripture, v.ordinal
WITH v.scripture AS scripture, count(v) AS matches, collect(v)[0..$perScripture] AS hits
UNWIND hits AS hit
MATCH (hit)-[:IN]->(ch:ScriptureChapter)
RETURN scripture, matches, hit.name AS reference, hit.text AS text, hit.original AS original, ch.name AS chapter
ORDER BY scripture, hit.ordinal

MeaningAcrossScriptures

“Nearest chapters by meaning” — run once per scripture, scoped by its tag.

MATCH (c:Concept {value: $query})-[r:RELEVANT_TO]->(d:Document)
WHERE 'scripture' IN d.tags AND $scripture IN d.tags
MATCH (ch:ScriptureChapter {documentUri: d.uri})<-[:IN]-(v:Verse)
WITH r, ch, v ORDER BY v.verse
WITH r, ch, collect({reference: v.name, text: v.text})[0..$verses] AS opening
RETURN r.rank AS rank, ch.scripture AS scripture, ch.name AS chapter, r.score AS score, r.snippet AS matched, opening
ORDER BY rank

SummarizeAcrossScriptures

“What it says” — one model summary per scripture of the verses using the word.

MATCH (v:Verse)
WHERE toLower(v.text) CONTAINS toLower($term)
WITH v ORDER BY v.ordinal
WITH v.scripture AS scripture, count(v) AS matching, collect(v)[0..$maxVerses] AS verses
UNWIND verses AS v
RETURN scripture, matching,
       summarize(v.name + ': ' + v.text, 'What these verses of one scripture say about ' + $topic + ' — its teaching, its stories and its figures of speech — in a few short points, each citing the verse references it rests on.') AS summary
ORDER BY matching DESC

SummarizeMeaningAcrossScriptures

“What it says”, in meaning mode — one call per scripture, two at a time.

MATCH (c:Concept {value: $query})-[r:RELEVANT_TO]->(d:Document)
WHERE 'scripture' IN d.tags AND $scripture IN d.tags
MATCH (ch:ScriptureChapter {documentUri: d.uri})<-[:IN]-(v:Verse)
WITH ch, v ORDER BY v.ordinal
RETURN ch.scripture AS scripture, collect(DISTINCT ch.name) AS chapters,
       summarize(v.name + ': ' + v.text, 'What these chapters of one scripture say about ' + $query + ', in a few short points, each citing the verse references it rests on. If they do not address it, say only that this scripture does not speak of it here.') AS summary

ReadScriptureChapter

the reader — a chapter with its original text and its parallels.

MATCH (ch:ScriptureChapter {name: $chapter})<-[:IN]-(v:Verse)
OPTIONAL MATCH (v)-[:CORRESPONDS_TO]-(o:Verse)
WITH ch, v, collect(o.name) AS parallels
RETURN ch.scripture AS scripture, ch.name AS chapter, v.verse AS verse, v.name AS reference,
       v.text AS text, v.original AS original, parallels
ORDER BY verse

AskScriptures

“Ask a question instead” — the agentic retrieval loop.

MATCH (c:Concept {value: $question})-[r:RELEVANT_TO {via: 'agentic-rag', intent: 'find the scripture chapters, in any scripture, that teach, narrate or command what the question asks about'}]->(d:Document)
WHERE 'scripture' IN d.tags
MATCH (ch:ScriptureChapter {documentUri: d.uri})
RETURN r.rank AS rank, ch.scripture AS scripture, ch.name AS chapter, r.score AS fit, r.snippet AS evidence
ORDER BY rank
LIMIT $limit

What an empty panel means

“No verse uses …” — the scripture's English text has no verse containing the word or stem. It is an answer: the Quran never uses “circumcis”. Try the meaning mode, or another form of the word. “Its nearest chapters do not speak of …” — the model read the closest chapters by meaning and judged they do not address the topic; it says so rather than summarising them as if they did. “No chapter of this scripture is searchable by meaning yet” — its chapter documents are not ingested (yet); the other panels still answer. A red panel is an error from the appliance, shown as it came.

What the appliance did that a conventional stack could not

Six scriptures from four realms, written separately, answer one query because each declared its types as children of the same vocabulary — no integration code and no shared schema migration, and a seventh realm appears as a column the moment it is installed. The meaning search is a relationship in the same Cypher as the graph walk ((:Concept)-[:RELEVANT_TO]->(:Document) then back to the chapter's verses), not a separate vector service whose results are joined in application code. The summaries are a Cypher aggregation (summarize) grouped by scripture like count would be. And the parallels are derived edges: a scripture's realm states a rule, and the graph carries the edges for every view without anyone storing them.
